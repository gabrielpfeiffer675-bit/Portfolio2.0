BLOC 1Compétence 1.3 : Mettre en place et vérifier les niveaux d’habilitation associés à un service

Descriptif de la preuve : Isolation stricte des traitements applicatifs Back-end selon le profil de l'utilisateur stocké en Session. Les fonctionnalités de modification (CRUD) sont bloquées en amont si l'utilisateur possède uniquement le rôle Technicien.

Document.php (Contrôleur CodeIgniter 3 — Guard de rôle) 
public function ajouter() {
    // Vérification de l'existence de la session et du niveau d'habilitation
    $user_role = $this->session->userdata('role');
    
    if (!$this->session->userdata('logged_in') || $user_role !== 'Admin') {
        // Redirection ou blocage si les habilitations sont insuffisantes
        show_error("Accès refusé : Vous ne disposez pas des habilitations requises.", 403);
        return;
    }
    
    // Suite du traitement pour les administrateurs
    $this->load->view('templates/header');
    $this->load->view('documents/ajouter');
    $this->load->view('templates/footer');
}
BLOC 1Compétence 1.5 : Gérer des sauvegardes

Descriptif de la preuve : Planification et exécution manuelle d'une stratégie de sauvegarde des ressources pour parer à toute perte de données en cours de développement solo.

Procédure d'archivage hebdomadaire appliquée :

  1. Fréquence : Chaque vendredi soir en fin de session de stage.
  2. Export de données : Génération d'un dump SQL complet (structure et données) via HeidiSQL nommé didiland_docs_YYYYMMDD.sql.
  3. Archivage des sources : Compression du dossier racine du projet /laragon/www/didiland-docs/ au format standardisé ZIP.
  4. Externalisation : Duplication des archives sur deux supports physiques amovibles distincts (clés USB de sauvegarde) conservés hors du lieu de développement.

BLOC 2Compétence 2.3 : Résoudre des incidents liés aux applications

Descriptif de la preuve : Résolution d'une anomalie logicielle relative à l'encodage système sous Windows, corrompant les caractères accentués lors de la génération à la volée des archives ZIP de téléchargement.

Remappage d'encodage via strtr() (PHP) 
public function encoder_nom_fichier($nom) {
    // Tableau d'équivalence pour convertir les accents UTF-8 vers la table CP850 / Windows-1252
    $trans = array(
        'é' => 'e', 'è' => 'e', 'ê' => 'e', 'à' => 'a', 
        'î' => 'i', 'ô' => 'o', 'û' => 'u', 'ç' => 'c'
    );
    // Nettoyage de la chaîne de caractères avant intégration au composant ZipArchive
    return strtr($nom, $trans);
}

BLOC 5Compétence 5.1 : Réaliser les tests d’intégration et d’acceptation d’un service

Descriptif de la preuve : Code défensif Back-end (règle métier d'intégrité référentielle) empêchant les opérations de suppression d'aboutir en BDD si des dépendances de clés étrangères subsistent.

Attraction_model.php (Vérification relationnelle avant suppression) 
public function verifier_et_supprimer($id_attraction) {
    // Exécution d'une requête COUNT pour identifier si des notices référencent ce manège
    $this->db->where('id_attraction', $id_attraction);
    $nombre_notices = $this->db->count_all_results('DOCUMENT');

    if ($nombre_notices > 0) {
        // Règle d'intégrité enfreinte : Suppression rejetée
        return false;
    }

    // Autorisation de la suppression car aucune dépendance n'est détectée
    $this->db->where('id', $id_attraction);
    return $this->db->delete('ATTRACTION');
}

BLOC 6Compétence 6.1 & 6.2 : Développement professionnel et Veille informationnelle

Descriptif de la preuve : Intégration des recommandations de l'ANSSI relatives aux fonctions de hachage cryptographique et à la gestion des comptes utilisateurs.

Note de veille cryptographique : L'utilisation d'algorithmes de type MD5 ou SHA-1 pour le stockage des mots de passe est proscrite en raison des vulnérabilités aux collisions. Conformément aux recommandations de l'ANSSI, le hachage doit être géré avec des fonctions à coût configurable.

Auth.php (Vérification cryptographique BCRYPT) 
// Exemple d'implémentation de la vérification applicative
public function valider_connexion($password_saisi, $password_hache_bdd) {
    // password_verify gère de manière native la comparaison constante contre les attaques temporelles
    if (password_verify($password_saisi, $password_hache_bdd)) {
        return TRUE;
    }
    return FALSE;
}
